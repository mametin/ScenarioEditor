# Phase 3 実装と検証

2026-11-09。本文、タイプ定義、設定資料を並行実装し、共通のSnapshotと自動保存へ統合。

## 使い方

1. 概要でプロジェクトを作成・選択する。
2. 「執筆」でノードを選び、本文を編集する。グラフの詳細からも移動できる。
3. 「設定資料」でNPC・場所・用語・アイテムを登録する。
4. 本文下の「設定資料・ノードへの参照を挿入」から表示モードを選択する。
5. 「タイプ」で独自タイプと入力項目を設定。「タグ」で名称・色と一括付与を管理する。

## 設計判断

- 保存形式v1は維持。独自ContentとTiptap JSONの変換アダプターを設けた。
- 既存本文がTiptapの構造で表現できない場合、勝手に正規化して保存せず編集を止める。
- 変換に失敗した入力はエディタ内とsessionStorageに退避し、救出JSONをダウンロードできる。ストレージ自体の失敗は表示する。救出JSONは通常のプロジェクトJSONとは別形式で、通常の取り込み対象ではない。
- 名前変更時はIDで参照先を解決。正式名・別名は追従し、固定表記は変わらない。削除された資料の参照と説明Documentは保持する。
- フィールドの削除は確認付き非表示で実現。値・定義は保持し、再表示できる。タイプ変更も旧フィールドを削除しない。
- 設定資料のカスタムフィールドは全ノードタイプの可視フィールド定義を共有する。カテゴリ専用の定義はまだ設けない。
- 執筆・設定資料画面へ移るとグラフをアンマウントし、そのグラフUndo履歴をリセットする。別画面で変更した本文やタグを古いグラフ履歴で巻き戻さないため。IndexedDBの保存履歴は維持する。

## 検証

単体テスト51件、型チェック、本番ビルド成功。対象は保存・競合・グラフに加えて、本文JSON変換、参照3モード、削除・使用箇所、フィールド値保持、タグ一括操作、救出データ。

実ブラウザで検証用プロジェクトを作り、日本語本文入力、資料作成、本文への参照挿入、クリックで詳細へ移動、名称変更の追従、使用箇所表示、再読み込み後の復元を確認した。

未検証: 実機スマートフォン、日本語IMEの変換途中操作、巨大本文性能、全9型入力と全書式ボタンのブラウザ回帰試験。Phase 4のアウトライン・Markdown/PDF、Phase 5のGitHub同期、Phase 6のPWAは未実装。
